# 光标拆章与相邻合并

在作者工作台打开任意章节，将光标放在正文中要开始下一章的位置，再点「从光标处拆为下一章」，或按 Ctrl / ⌘ + Enter。选中一段文字时，使用选区开头作为断点；不是只移动被选中的文字。

确认窗口预览断点前后文字、两侧字符数、新章标题及受影响的后续编号。确认后，光标前的文字保留在当前章，后面的全部文字原样移入紧接的新章，并自动打开新章，可继续拆分。不会自动去除空行、空格或改写正文；不能在文本首尾或空白处拆出空章。

## 编号

- 左侧目录序号始终按实际章节顺序重新显示。
- 章名中的编号可选择顺延，默认开启；例如第一章拆分后生成第二章，原第二章变第三章，描述性的章名保留。
- 支持中文数字、阿拉伯数字、全角数字及带数字的 Chapter / Episode / EP. 前缀；保留数字前导零及原有前缀间距。
- 不同类型编号不混改。遇到明确分卷标题或编号重新开始时停止顺延；序章、番外和无编号标题保留。罗马数字、纯数字章名等未支持样式仍可手动改名，不做盲目顺延。
- 新章标题可自定义。取消顺延只保留章名原状，目录序号仍会更新。

## 合并、撤销与备份

「合并下一章」把下一章正文追加到当前章，中间增加两个换行，保留当前章标题；下一章标题不自动写入正文。后续同类编号可向前顺延。

拆分、合并和撤销都在同一 IndexedDB 事务中保存新草稿及独立的操作前备份，失败时一起回滚。备份可在草稿箱找到，也可导出。修改过的正文移除旧的导入行号，避免继续显示过期来源位置。

「撤销上次拆分 / 合并」为当前会话中每份草稿保存一次最近操作快照。撤销会恢复该操作前的全部章节，操作后对章节的额外编辑也会回退，因此先提示并备份当前版本；作品资料保留。刷新后会话撤销不可用，仍可通过草稿箱中的独立备份恢复。

拆分与合并继续执行1000章、200万字符及标题100字限制。操作只保存本机草稿，不自动更新公开作品，发表仍需导出并提交 GitHub。

实现：`src/chapter-edit.js`、`src/chapter-edit-ui.js`；验证：`tests/chapter-edit.test.js`，包括字符保留、编号格式、卷边界、空章及字符内部断点、容量、操作不可变性和事务失败回滚。
