# 论坛连载整理（v2.6.0 / 引擎 3.2）

适用于含重复楼层、作者资料和时间的连载文本。当前识别明确的 NGA 式帖子组合，不宣称支持任意论坛。全部规则在本机执行，不需要联网模型。

## 使用

选择文档后自动识别。预览中的“论坛连载”显示帖子数与建议核对位置，点击即可跳到原文。标题在楼尾时，可能为点题或下一话预告，需要结合上下文判断。可以取消自动整理、按普通文档处理，再恢复自动整理；确认前不改草稿。

“一键分章”也支持同一套角色识别。“调整分章选项”中可关闭论坛识别；预览的论坛结构清单可直接进入原文校对。单文件替换或导入空草稿时，保存转换后的原文快照，供后续选择“上次保存的原文”重新分析。向已有作品追加文件、批量导入时，不用单个文件替换整部作品的原文快照。

行号对应**导入转换后的文本**，不是 Word 页码或原文件字节位置。转换会规范化换行、首尾空白等；一键整理会显示清洗行与导入原文行的对应关系。

## 处理原则

1. 至少三个可信帖子头联合触发：楼层与 UID、级别/注册资料、时间同时出现。代码围栏中的示例不作为帖子。
2. 仅确认的帖子头、编辑记录、附件控件和完整导航组合进入元信息。投票数字只有紧随帖子头且带原始零宽控件标记时归档；普通数字不批量删除。
3. 标题分成开始、结束、说明、近邻重复和分篇。章末“完”、作者剧情说明不作为新章，文字仍留在正文；同篇近邻相同标题合并候选，重复文字仍在正文。
4. 分篇要求短标题以篇/卷/部结束、后接第零或第一章，并已有章节序列。分篇写入 `volume`；原始分篇标题放入归档，允许卷内重新编号。
5. 保留骰子、编号选项、角色台词、引用和符号。论坛模式不使用通用“纯符号/引用即杂讯”的清洗，也不自动合并短章；长度不等同章节语义。
6. 楼尾标题、同名续更等作为建议核对位置。规则证据不代表正确率；只有覆盖检查通过才允许确认。

## 数据与实现

- `src/forum-serial.js`：帖子探测、元信息范围、标题角色、分篇归属。
- `src/import-analysis.js`：文件导入适配。使用 `archiveLines` 归档元信息，保持原文行号与字符偏移，供普通校正和光标拆章共用。
- `src/chapter-analysis.js`：核心切分与覆盖校验。`archiveLines` 为 1 起始、范围内的行号；元信息不成为可选标题。
- `src/smart-split.js`：一键整理路径，提供清洗后行到导入原文行的 `sourceLines` 映射。
- `src/import-review.js`、`src/boundary-review-ui.js`、`src/visual-source-ui.js`：疑点定位与人工确认；修改分界后继续保留分篇。

文件导入的论坛资料在 `frontMatter` / 草稿 `importNotes` 中保留；原文快照和作者草稿备份也是私有资料。公开作品、阅读副本与结构报告不包含这些资料。新增的帖子作者与 UID 仅用于本机识别，不进入公开结构报告。

## 验证与限制

`tests/forum-serial.test.js` 使用独立合成数据，覆盖最小触发、代码围栏、八话与前言、章末/说明/重复、骰子保留、坐标映射、归档后的光标拆分、分篇重编号、关闭模式和结构报告隐私。用户提供的真实手稿仅在本地验证，不进入仓库或公开评测。

规则仍可能无法判断楼尾标题究竟是本话点题还是下话预告，也不会自动判断帖子内容是否属于读者回复。多作者文本保留各作者正文，不自动删除。没有正式标题时，保留整篇，交由人工选点或示例学习。不能把单份本地文件的识别结果当作准确率；现有合成结构基准与本功能回归分开解释。
